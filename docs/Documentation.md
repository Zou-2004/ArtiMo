# ArtiMo Documentation

This document keeps the operational details out of the main README.

## Workflow

The normal ArtiMo flow is:

```text
URDF + referenced meshes/textures
  -> scripts/textured.sh
  -> asset folder with mobility.urdf + animated_textured_<asset>.glb
  -> scripts/run_agent.sh
  -> causal.json + plan.json + trajectory.jsonl + plan_animated.glb
```

Optional follow-up steps:

```text
plan.json + causal.json -> Isaac Sim bundle/video
prediction GLB/trajectory -> benchmark 3D/2D evaluation
```

If the asset already contains `mobility.urdf` and
`animated_textured_<asset>.glb`, start directly from [Run ArtiMo](#run-artimo).

## Environment

Install dependencies:

```bash
conda create -n artimo python=3.10 -y
conda activate artimo
pip install -r requirements.txt
```

Configure keys and render paths:

```bash
cp configs/env.example .env
# edit .env
set -a
source .env
set +a
```

Required for model calls:

- `OPENAI_API_KEY` or another OpenAI-compatible key, or
- `GEMINI_API_KEY` for Gemini-backed VLM calls.

Recommended for rendering:

```bash
export BLENDER_BIN=/path/to/blender
export CODEX_LOOP_MOTION_RENDER_BACKEND=blender
export CODEX_BLENDER_USE_GPU=1
export CODEX_BLENDER_PERSISTENT=1
```

Optional PyTorch3D acceleration:

```bash
export CODEX_TORCH_RASTER=1
export CODEX_PYTORCH3D_VIS_RASTER=1
export CODEX_TORCH_RASTER_ALLOW_CPU=1
```

Install PyTorch3D from the official instructions:
https://github.com/facebookresearch/pytorch3d/blob/main/INSTALL.md

## Input Assets

ArtiMo expects one directory per articulated object:

```text
asset_name/
  mobility.urdf
  meshes_or_textured_objs/
  textures_or_images/
  animated_textured_<asset_name>.glb
  animated_textured_<asset_name>.report.json
```

The URDF defines the joint tree, link visuals, origins, mesh paths, and joint
limits. Mesh paths are resolved relative to the URDF.

For a raw asset with `mobility.urdf`, build the textured GLB with:

```bash
bash scripts/textured.sh --root /path/to/data/causal_data asset_name
```

For an external asset with a differently named URDF:

```bash
bash scripts/textured.sh --urdf /path/to/asset_name/model.urdf
```

The script canonicalizes URDF names by default, writes `mobility.urdf`, creates
`animated_textured_<asset_name>.glb`, and records mappings in
`urdf_name_map.json`.

To process a full folder:

```bash
JOBS=6 bash scripts/textured.sh --root /path/to/data/causal_data --all
JOBS=6 bash scripts/textured.sh --root /path/to/data/not_causal_data --all
```

Useful controls:

```bash
INITIAL_POSE_MODE=zeros
FRAMES_PER_JOINT=36
MAX_PREVIEW_JOINTS=8
CANONICALIZE_URDF_NAMES=1
CANONICALIZE_JOINT_NAMES=1
```

## Articraft Assets

ArtiMo can process URDF assets generated by
[Articraft](https://github.com/mattzh72/articraft):

```bash
bash scripts/textured.sh \
  --urdf /path/to/record_materialization/<record_id>/model.urdf
```

Then run ArtiMo with that materialized folder as `--asset_root`. The same path
supports referenced OBJ meshes and URDF primitive visuals such as `box`,
`cylinder`, and `sphere`.

## Run ArtiMo

```bash
scripts/run_agent.sh \
  --asset_root /path/to/asset \
  --action_text "fully open the microwave door" \
  --out_root outputs/microwave1_fully_open \
  --vlm_model gemini-3.1-pro-preview \
  --llm_model gpt-5.4 \
  --api_provider openai \
  --use_glb_scene auto \
  --enable_loop \
  --enable_coverage_loop \
  --enable_motion_loop \
  --coverage_max_iters 1 \
  --motion_max_iters 3
```

Main outputs:

```text
<out_root>/<asset>/
  images/
  output.json
  causal.json
  plan.json
  trajectory.npz
  trajectory.jsonl
  plan_animated.glb
```

Coverage and motion-diagnosis artifacts are stored under
`<out_root>/<asset>/loop/`.

## Mask-Conditioned Input

Pass one or more mask images with `--input_masks`:

```bash
CODEX_LOOP_MOTION_RENDER_BACKEND=blender \
CODEX_BLENDER_USE_GPU=1 \
python tools/run_agent_single.py \
  --asset_root /path/to/data/not_causal_data/7_drawers \
  --action_text "open the masked areas(shown in translucent green area) as shown on the input mask image only for 2 seconds and slowly close for 2 seconds" \
  --out_root outputs/masked_7_drawers \
  --vlm_model gemini-3.1-pro-preview \
  --llm_model gpt-5.4 \
  --input_masks /path/to/masks/7_drawer_mask.png \
  --enable_loop \
  --enable_motion_loop \
  --motion_max_iters 3 \
  --disable_numeric_verify
```

The VLM input manifest is written to
`<out_root>/<asset>/prompts/vlm_input_manifest.json`.

## Execute An Existing Plan

```bash
python tools/run_plan.py \
  --asset_root /path/to/asset \
  --plan_json /path/to/plan.json \
  --out /path/to/output/animation \
  --trajectory_npz /path/to/output/animation/trajectory.npz \
  --trajectory_jsonl /path/to/output/animation/trajectory.jsonl \
  --export_animated_glb \
  --use_glb_scene auto
```

## Isaac Sim Export

Compile an Isaac Sim bundle from an existing `causal.json` and `plan.json`:

```bash
scripts/compile_isaacsim_bundle.sh \
  --asset_root /path/to/asset \
  --causal_json /path/to/causal.json \
  --plan_json /path/to/plan.json \
  --bundle_dir outputs/isaacsim_bundle
```

Run it with Isaac Sim:

```bash
ISAAC_PYTHON=/path/to/isaacsim/python.sh \
  outputs/isaacsim_bundle/run_isaacsim_executor.sh
```

Bundle outputs:

```text
outputs/isaacsim_bundle/outputs/
  <asset>_isaac.mp4
  frames/frame_*.png
  trajectory.npz
  trajectory.jsonl
  execution_report.json
```

The bundle contains Python code that imports the URDF as an Isaac articulation,
applies joint/base controls from the plan, captures frames, and encodes an MP4.
